## 3. Сделано в коде, но ни разу не проверено (device-приёмка)

### 3.1 iOS — T12–T36 (реальный iPhone, Mac с Console.app, SIM с IPv6)

Валидация Фазы 7 (build 18) по построению не могла поймать пять классов проблем — именно их и надо проверить в первую очередь:

- **T15** — отключение реально возвращает интернет (blackhole 1.1), 5 раз + не-кнопочные пути (sign-out, 402). Начинать с него.
- **T14** — Wi-Fi↔LTE **под нагрузкой** ×3, критерий по логу расширения (окно утечки 1.2).
- **T12** — IPv6-leak (ожидается «нет IPv6», а не адрес ноды).
- **T13** — DNS-leak в трёх прогонах (после смены сети и после фона).
- **T16** — автоподъём после перезагрузки (on-demand реализован 2026-07-28 — «неприменимо» помечать нельзя).
- **T23** — кил расширения / jetsam: `JetsamEvent-*`, `rpages`; заодно связка kill-switch × Clash API.
- **T24** — после disconnect/logout на диске нет конфига с кредами (`active-config.json`, `start_options.plist`, `diagnostics.txt`, `Caches/stderr.log`) + незашифрованный бэкап.
- **T25** — support bundle без маркерного домена.
- **T26–T36** (вторая волна, поведение изменено вычиткой): смена сервера ×10, счётчики трафика (**полностью новое поведение** — раньше всегда 0), `system`-стек + MTU 1280 (**самая рискованная правка аудита** — speedtest ×3 против build 18 + сессия 2 ч, пропали ли jetsam-килы), таймауты старта (~40 с), sleep/wake за ночь, Clash API снаружи, первый коннект без `cache_file`, батарея/интервалы watchdog'а, kill-switch, fallback App Group, долгая сессия под гонками.
- Раздел 2 чек-листа (K1–K7, L1–L6) — не начат целиком; L6 (H2 по сотовой — оператор режет UDP/443) — главное подозрение по жалобе «подключено, но нет интернета».
