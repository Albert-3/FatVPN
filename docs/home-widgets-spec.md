# Виджеты на домашний экран (Android + iOS)

Статус (2026-07-28): **написано, на устройстве не проверено ничего.**

Отдельная кнопка вкл/выкл (2026-07-28, вторая итерация): кнопка теперь и
подключает — на Android без открытия приложения вообще, на iOS 17+ как
настоящая кнопка внутри плитки, — а тап мимо неё только открывает приложение.
Собрано: `flutter analyze` чисто, `flutter test` 208 тестов зелёные (15 новых —
`test/widget_power_button_test.dart`), debug и release APK собираются, точка
входа фонового движка присутствует в release-снапшоте (проверено в
`libapp.so`). **На устройстве не запускалось ни разу**, iOS-часть, как обычно,
даже не компилировалась здесь — только через Codemagic.

* Android — собирается локально в debug **и в release**: R8 сохраняет
  `FatVpnWidgetProvider` (он в манифесте), shrinker не выкидывает раскладки и
  строки виджета, ресивер с тремя action-ами присутствует в `app-release.apk`.
* Android, **на устройстве** (Redmi Note 7, Android 10, debug-сборка,
  2026-07-28): виджет ставится на экран и рисуется — статус, локация, кнопка;
  приложение реально пишет снапшот (`shared_prefs/fatvpn_widget.xml` содержит
  `{"v":1,"state":"disconnected","lang":"ru","signedIn":true,…}`), то есть канал
  Dart → нативка работает. Проверено только состояние «отключено»: **включённый
  туннель на виджете никто не видел** — ни зелёная кнопка, ни идущие часы, ни
  флаг страны, ни отключение тапом (TW2–TW9).
* iOS — Swift здесь не компилируется вообще (нет Xcode), проверка только через
  Codemagic. Скрипт `add_widget_target.rb` не запускался ни разу.
* Dart — `flutter analyze` чисто, `flutter test` 187 тестов зелёные (из них 12
  новых — мост снапшота и «стоп извне приложения — не сбой»).

Виджет показывает состояние туннеля, локацию и время сессии, а по нажатию —
подключает или отключает VPN. Работает и когда приложение выгружено: это
основное требование, и оно определило всю архитектуру ниже.

## 1. Что виджет умеет, а что нет

Кнопка питания — **отдельная кнопка**, а не «вся плитка». Тап по ней включает или
выключает VPN; тап по любому другому месту виджета открывает приложение и больше
ничего не делает.

| Действие | Android | iOS |
|---|---|---|
| Показать статус/локацию/таймер без запуска приложения | ✅ | ✅ |
| **Отключить** туннель кнопкой, не открывая приложение | ✅ | ❌ (открывает приложение, оно отключает) |
| **Подключить** кнопкой, не открывая приложение | ✅ | ❌ (открывает приложение, оно подключает) |
| Тап мимо кнопки открывает приложение, не трогая туннель | ✅ | ✅ (iOS 17+; ниже — вся маленькая плитка переключает) |
| Первый тап «вкл» без выбранной страны = лучший сервер | ✅ | ✅ |
| Экран блокировки (accessory-виджеты) | — | ✅ (iOS 16+) |

**Что «подключить» значит на самом деле.** Поднять туннель — это не «запустить
сервис»: нужна живая проверка подписки (`/servers` отвечает 402, как только
подписка кончилась), свежий конфиг из `/config`, выбор узла и, на первом запуске,
системный диалог согласия на VPN. Стартовать из последнего конфига на диске
означало бы переподключать пользователя, которому панель уже отозвала ключ, — это
ровно тот класс дефектов, который аудит 2026-07-27 нашёл в iOS-логике on-demand.
Поэтому **вторая реализация подключения на Kotlin не писалась**: Android запускает
тот же самый dart-код в фоновом Flutter-движке (§3), а iOS передаёт действие
приложению (§4).

**Почему на iOS кнопка всё-таки открывает приложение.** Любое обращение к
`NETunnelProviderManager` требует entitlement `com.apple.developer.networking.
networkextension`. У виджет-расширения его нет и не будет: это отдельный App ID,
которому пришлось бы включать NE-capability в портале, ради одной кнопки. Виджет
на iOS не разговаривает с туннелем вообще — только читает снапшот и просит
приложение сделать дело. Отдельной кнопкой (а не «вся плитка — переключатель»)
она там стала за счёт App Intent (iOS 17+), см. §4.

**Куда подключается «вкл».** В страну, которую пользователь выбрал в приложении,
а если не выбирал ни разу (или выбрал «Лучший сервер») — в самый быстрый узел
из всей подписки. Выбор живёт на диске (`SelectedLocationStore`, ключ
`selected_country` в secure storage): раньше он лежал только в состоянии
`HomeScreen`, то есть терялся при каждом перезапуске — а виджету, который
подключается вообще без UI, взять его больше неоткуда. Побочный эффект, которого
как раз хотелось: приложение теперь тоже помнит выбранную страну между запусками.
Выход из аккаунта стирает эту запись вместе с сессией (`TokenStorage.clear`).

## 2. Общая модель данных

Один снапшот, два писателя, один читатель.

```
Flutter (HomeWidgetBridge)                 PacketTunnel / VpnService
  state, lang, signedIn,                     state, connectedAt
  locationLabel, flagEmoji,                  (когда приложения нет в живых)
  connectedAt, expiresAt
            \                                     /
             \                                   /
              ▼                                 ▼
        Android: SharedPreferences        iOS: App Group UserDefaults
        `fatvpn_widget` + плагинный        `group.com.fatvpn.fatvpnApp`,
        `signbox_mm_runtime`               ключ `fatvpn.widget.snapshot`
                          \        /
                           ▼      ▼
                    FatVpnWidgetProvider / FatVpnWidget
```

Поля (`lib/services/home_widget_bridge.dart`, версия `v: 1`):

| Поле | Кто пишет | Зачем |
|---|---|---|
| `state` | приложение; на iOS ещё и расширение туннеля | текст статуса |
| `lang` | приложение | язык, выбранный **в приложении**, а не в системе |
| `signedIn` | приложение | без подписки кнопка питания только открывает приложение |
| `locationLabel`, `flagEmoji` | приложение | «🇩🇪 DE» либо localized «Лучший сервер» |
| `connectedAtMillis` | приложение; на iOS ещё и расширение | самотикающие часы сессии |
| `expiresAtMillis` | приложение | зарезервировано под показ остатка подписки |

Два писателя владеют **разными половинами** снапшота, поэтому:
* `HomeWidgetBridge.update()` патчит поля, а не заменяет запись целиком —
  `main.dart` знает про сессию и язык, `HomeScreen` знает про туннель и локацию;
* на iOS расширение вызывает `patchTunnelState()`, а не `write()` — иначе
  on-demand-старт стёр бы локацию и язык до следующего открытия приложения.

### Язык

Виджет рисуется системой, у него нет доступа к Dart-локализации. Строки лежат
нативно: `res/values(-ru)/strings.xml` на Android, `FatVpnWidgetStrings.swift` на
iOS. Резолвятся **не по локали телефона**, а по `lang` из снапшота: язык в
приложении — пользовательская настройка (`LocaleController`), и виджет,
говорящий по-английски рядом с русским приложением, читается как баг.
Системная локаль — только фолбэк для установки, которую ещё ни разу не открывали.

## 3. Android

Файлы:

```
android/app/src/main/kotlin/com/fatvpn/fatvpn_app/widget/
  FatVpnWidgetProvider.kt   AppWidgetProvider: отрисовка, тапы, стоп туннеля
  FatVpnWidgetState.kt      чтение состояния из двух хранилищ + сверка с живым сервисом
  FatVpnWidgetChannel.kt    MethodChannel `fatvpn/widget` ← Dart
  WidgetConnectService.kt   foreground-сервис: фоновый Flutter-движок для «вкл»
lib/main.dart               widgetConnectMain() — точка входа этого движка
lib/services/widget_connect_runner.dart   что он делает
android/app/src/main/res/
  layout/widget_fatvpn_compact.xml, widget_fatvpn_wide.xml
  xml/fatvpn_widget_info.xml
  values/strings.xml, values-ru/strings.xml, values/colors.xml
  drawable/widget_*.xml, ic_widget_power.xml
```

**Откуда берётся состояние.** Плагин `singbox_mm` уже пишет своё состояние в
`SharedPreferences("signbox_mm_runtime")` и **широковещательно** рассылает каждое
изменение (`com.signbox.singbox_mm.action.STATE`, защищено signature-permission
`${applicationId}.permission.SIGNBOX_STATE`, с `setPackage`). Виджет-ресивер
подписан на этот broadcast — поэтому остановка туннеля из шторки уведомлений
обновляет виджет без участия приложения.

**Снапшот «connected» ещё не значит, что туннель жив**: force-stop или убийство
по памяти оставляют запись навсегда. Плагин сверяется со своим процессным флагом
(`VpnServiceLiveness`), который виджету не виден (`internal`), поэтому
`FatVpnWidgetState` делает эквивалентную сверку через
`ActivityManager.getRunningServices` — с Android 8 он возвращает только сервисы
собственного приложения, то есть ровно то, что нужно.

**`updatePeriodMillis = 0`.** Системный тик не может быть чаще 30 минут — для
индикатора соединения бесполезен. Обновляют: broadcast туннеля, публикация из
приложения и сам тап. Часы сессии тикают сами внутри `Chronometer`.

**Подключение: фоновый Flutter-движок.** Тап по кнопке при опущенном туннеле
запускает `WidgetConnectService` — foreground-сервис, который поднимает
`FlutterEngine` без окна и вызывает в нём `widgetConnectMain` (`lib/main.dart`).
Дальше работает `WidgetConnectRunner`: читает сессию из secure storage, при
необходимости обновляет access-токен, спрашивает `/servers` + `/config`, выбирает
узел (выбранная страна или лучший по пингу) и поднимает туннель через тот же
`VpnController`, что и главный экран. По итогу сервис получает вердикт по каналу
`fatvpn/widget_connect` и уходит.

Почему именно так, а не иначе:

* **не ресивер** — на broadcast-ресивер дают около десяти секунд, а здесь два
  сетевых раунда и пинг всех кандидатов; процесс без foreground-сервиса убивается
  сразу после `onReceive`;
* **не Kotlin-реализация подключения** — это была бы вторая, отстающая копия
  логики выбора узла, парсинга подписки и сборки конфига;
* **`FlutterEngine(context, null, false)`** — однокачественный конструктор
  регистрирует плагины сам, рефлексией, внутри конструктора; вместе с явным
  `GeneratedPluginRegistrant.registerWith` это дало бы двойную регистрацию всех
  плагинов на одном движке;
* **точка входа лежит в `lib/main.dart`**, а не в отдельном файле: компилятор
  собирает программу от корневой библиотеки, и точка входа, которую никто не
  импортирует, просто не попала бы в release-снапшот. Проверено на собранном
  APK — строка `widgetConnectMain` есть в `lib/arm64-v8a/libapp.so`;
* **`specialUse`/`vpn`** как тип сервиса — тот же, что у самого туннеля; сервис
  и живёт-то ровно столько, сколько идёт подключение.

Приложение открывается только в трёх случаях, каждый из которых требует экрана:
нет сессии, подписка кончилась (`402`), или плагин просит системный диалог
согласия на VPN (`NO_ACTIVITY` / `PERMISSION_DENIED` — это первое подключение на
устройстве). Тогда движок возвращает `handOverToApp`, и сервис открывает
`fatvpn://widget/connect`, чтобы приложение довело дело до конца.

**Пока идёт подключение** виджет не должен выглядеть мёртвым: тап ставит маркер
`connectRequestedAt` в своих prefs, и `FatVpnWidgetState` рисует «Подключение…»,
пока туннель не заговорит сам. Маркер снимает сервис по завершении, а его окно
(100 с) — страховка на случай убитого сервиса. Второй тап в этом состоянии
отменяет попытку (сервис останавливается), а не «выключает» туннель, которого
ещё нет.

**Безопасность тапа.** Провайдер виджета обязан быть `exported` (иначе лаунчер до
него не достучится), а значит любое приложение может послать ему explicit intent
— в том числе «выключить VPN», что для VPN не теоретическая проблема. Поэтому
тап аутентифицируется токеном: он лежит в приватных prefs и внутри `IMMUTABLE`
PendingIntent, который лаунчер не может переписать.

**Четыре раскладки** выбираются самим лаунчером через
`RemoteViews(Map<SizeF, RemoteViews>)` на API 31+; ниже — по
`OPTION_APPWIDGET_MIN_*`. Идентификаторы view во всех четырёх одинаковые,
поэтому код отрисовки один:

| Раскладка | Когда | Что внутри |
|---|---|---|
| `compact` | одна строка лаунчера (4×1, 3×1) | горизонтально: статус + локация, кнопка справа |
| `wide` | от 250×110dp (4×2) | то же, но три строки текста |
| `square` | узкая и от 110dp высотой | вертикально по центру: кнопка 50dp, статус, строка «локация + часы» |
| `square_large` | узкая и от 180dp высотой | то же, но с заголовком «FatVPN», кнопкой 78dp и текстом на ступень крупнее |

⚠️ **«2×2» — это не размер.** Замерено на Redmi Note 7 (MIUI, 4 колонки): две
ячейки дают **148×204dp**, то есть плитка в полтора раза выше, чем шире. С
кнопкой 50dp сверху и снизу оставалось по ~55dp пустой карточки — виджет
выглядел не «минималистично», а недоделанным. Отсюда `square_large`: порог 180dp
— это её собственная минимальная высота (12 + 16 + 8 + 78 + 10 + 21 + 3 + 18 + 12
≈ 178dp), а не «примерно большая плитка».

В квадратных раскладках **нет точки состояния**: кнопка большая, по центру, и
говорит то же самое тем же цветом, а точка сбоку от центрированного текста ломала
бы симметрию. Она остаётся в дереве как `GONE` — RemoteViews кидает исключение,
если попросить его тронуть view, которого нет, а код отрисовки один на все
раскладки. По той же причине текст в квадратах центрирован: первая версия
оставила его прижатым влево под центрированной кнопкой, и на домашнем экране это
читалось как ошибка вёрстки.

**2×2 — отдельный элемент в списке виджетов** (`FatVpnWidgetSquareProvider`,
`res/xml/fatvpn_widget_square_info.xml`, `targetCell 2×2`). Размер по умолчанию
живёт в XML провайдера, а XML — один на ресивер, поэтому второй предлагаемый
размер = второй ресивер. Класс пустой: он наследует всё у
`FatVpnWidgetProvider`, и какая раскладка нарисуется, решает **фактический**
размер плитки, а не то, каким провайдером её поставили — растянутый до четырёх
ячеек 2×2 станет широкой карточкой. `notifyWidgets` рассылает обновление обоим
компонентам (иначе 2×2 обновлялся бы только по системному тику, которого нет).
Заодно у старого провайдера появился `minResizeWidth=110dp` — уже поставленный
виджет теперь можно ужать до квадрата.

⚠️ **RemoteViews не масштабирует то, что не влезло — он это обрезает.** Первая
сборка отдавала трёхстрочную `wide` виджету высотой в одну строку, и на Redmi
Note 7 нижняя строка оказалась распилена пополам. Отсюда два правила, которые
легко сломать обратно:

* порог для `wide` сравнивается с **её собственной** высотой (`WIDE_HEIGHT_DP`),
  а не с верхней границей компактной; то же и у `square` — её высота считается
  от самой маленькой 2×2, которую может выдать лаунчер (110dp), и в этот бюджет
  влезают ровно три ряда: кнопка, статус, «локация + часы»;
* в `compact` и в `square` вторая строка одна, и её занимает локация: подсказка
  «Подключиться» рядом с ней ellipsis-илась вместе с локацией, а кнопка питания
  говорит то же самое без единого пикселя. Подсказка там появляется только когда
  сессии нет вовсе — тогда локацию показывать нечего.

**Палитра повторяет главный экран**: фон карточки — `AppColors.background`
(#0B1622), диск кнопки — `AppColors.card` (#152436), а во включённом состоянии
диск заливается акцентом с тёмным глифом. Это та же инверсия, что у большой
кнопки в приложении; сделанный сначала «фон карточки = #152436» превращал виджет
в серую плашку на обоях и прятал в ней кнопку.

## 4. iOS

Файлы:

```
ios/Shared/FatVpnWidgetSnapshot.swift   компилируется в Runner, PacketTunnel и виджет
ios/FatVpnWidget/
  FatVpnWidgetBundle.swift   @main
  FatVpnWidget.swift         SwiftUI: systemSmall/Medium + accessory (iOS 16+)
  FatVpnWidgetIntents.swift  App Intent кнопки питания (iOS 17+)
  FatVpnWidgetStrings.swift  EN/RU
  Info.plist                 NSExtensionPointIdentifier = com.apple.widgetkit-extension
  FatVpnWidget.entitlements  ТОЛЬКО App Group
ios/tool/add_widget_target.rb            создаёт таргет в Runner.xcodeproj
ios/Runner/AppDelegate.swift             канал `fatvpn/widget`
ios/PacketTunnel/PacketTunnelProvider.swift  patchTunnelState на старте/остановке
```

**Кнопка питания — App Intent (iOS 17+).** `SwiftUI.Link` внутри `systemSmall`
игнорируется: вся плитка была одним тапом, и «кнопка» на ней была нарисованной.
С iOS 17 внутри виджета работает настоящий `Button(intent:)`, и он сосуществует
с `widgetURL` плитки — ровно то разделение, которое требовалось: круг
переключает, всё вокруг открывает приложение. Интент (`FatVpnTogglePowerIntent`)
не трогает туннель (нечем — нет NE-entitlement): он кладёт `toggle` в общий App
Group и просит систему открыть приложение (`openAppWhenRun`).

Приложение забирает действие **само**, а не ждёт диплинка:
`AuthController.pollWidgetAction()` дёргает канал `fatvpn/widget` на старте и на
каждом resume, `AppDelegate` отвечает `FatVpnWidgetSnapshot.takePendingAction()`.
Так надо потому, что интент открывает приложение **без URL** — диплинка просто
нет. Побочно это чинит и риск: путь `fatvpn://` до Dart на iOS никогда не
проверялся (приложение на `SceneDelegate`), а этот путь от него не зависит.
Действие живёт 120 секунд (`pendingActionTTL`) — иначе тап, после которого
приложение так и не открылось, включил бы VPN при следующем запуске «сам по
себе».

> ⚠️ **Два условия, без которых кнопка не делает ровно ничего** — обнаружено на
> устройстве 2026-07-31 (виджеты нарисовались с настоящими данными, то есть App
> Group живой, а нажатие не давало ни запуска, ни ошибки):
>
> 1. `openAppWhenRun` означает, что систему просят выполнить интент **в процессе
>    приложения**. Бинарь, в котором типа интента нет, выполнить его не может —
>    поэтому `FatVpnWidgetIntents.swift` теперь член **обоих** таргетов
>    (`add_widget_target.rb` добавляет его и в Runner), а его availability
>    называет `iOS 17.0`, а не только `iOSApplicationExtension 17.0`.
>    `AppIntents`/`WidgetKit` линкуются в Runner слабо (`-weak_framework`):
>    deployment target приложения 13.0, и старое устройство должно суметь
>    **запустить** приложение, которое просто содержит этот тип.
> 2. Одного опроса мало. Интент выполняется, когда приложение уже активно, то
>    есть **после** и `AuthController.start()`, и колбэка `resumed` — оба уже
>    заглянули в почтовый ящик и нашли его пустым. Поэтому
>    `FatVpnWidgetSnapshot.requestAction` шлёт `actionRequestedNotification`,
>    `AppDelegate` пробрасывает её в Dart как `pendingActionAvailable`, а
>    `HomeWidgetBridge.listenForActions()` превращает это в ещё один
>    `pollWidgetAction()`. Само действие по-прежнему лежит в App Group и берётся
>    ровно один раз, так что push и poll не могут выполнить один тап дважды.
>
> Ни то, ни другое на устройстве пока не проверено — это гипотеза, собранная и
> отправленная в сборку, а не подтверждённое исправление.

**Вид кнопки (правка заказчика, 2026-07-31).** Кнопка теперь **сверху** плитки, а
не под текстом, и всегда зелёная — в цвет лого (`AppColors.accent`, `0x34D399`).
Раньше она красилась тем же цветом, что и точка статуса, то есть в отключённом
состоянии была серой; заказчик попросил зелёную. Состояние при этом не потерялось:
подключённая кнопка залита зелёным целиком (глиф — цветом фона), отключённая —
зелёный контур и зелёный глиф на почти прозрачной заливке. Серой она остаётся
ровно в одном случае — сессии нет, и это уже не кнопка. Точка статуса и строка
статуса свою семантику («зелёный = трафик защищён») сохраняют без изменений.
Android-виджет не трогали.

На iOS 16 и ниже интерактивных виджетов нет: на среднем виджете кнопка — `Link`
(остальное открывает приложение), на маленьком переключает вся плитка, потому
что виджет с нарисованной кнопкой питания, которая только открывает приложение,
хуже, чем виджет без кнопки.

**Таргет создаётся скриптом, а не руками**, ровно как `PacketTunnel`: Mac у
проекта нет, `Runner.xcodeproj` в репозитории не содержит ни одного расширения.
`add_widget_target.rb` идемпотентен и **обязан запускаться после**
`add_packet_tunnel_target.rb` — он же добавляет общий файл снапшота в таргет
туннеля. Оба шага прописаны в `codemagic.yaml` (workflows `ios-release` и
`ios-unsigned`).

**Bundle ID расширения: `com.fatvpn.fatvpnApp.FatVpnWidget`.** ⚠️ Перед первой
сборкой в App Store Connect нужно, чтобы этот App ID существовал и у него была
включена **App Groups** с `group.com.fatvpn.fatvpnApp`. Без capability подпись не
обязательно падает — entitlement может быть просто вырезан, и тогда
`UserDefaults(suiteName:)` вернёт nil, а виджет навсегда останется на фолбэке
«откройте приложение». Именно поэтому шаг `Verify App Group entitlement` в
`codemagic.yaml` теперь проверяет и `PlugIns/FatVpnWidget.appex` — сборка
покраснеет здесь, а не на телефоне тестировщика.

**Это и случилось: сборка 142 (2026-07-28) упала — `Signing for "FatVpnWidget"
requires a development team`.** Профиля для виджета в тот момент не существовало:
`ios_signing.bundle_identifier: com.fatvpn.fatvpnApp` ищет **подстрокой** (потому и
подхватывает `…​.PacketTunnel`), но заводит недостающее только когда не нашлось
*ничего* — а основной App ID нашёлся. Плюс профили в этой команде созданы руками, а
не API-ключом: Codemagic сам создаёт только сертификат, профиль — нет.
`xcode-project use-profiles` молча пропускает таргет без профиля, тот остаётся на
автоматической подписи без команды, и Xcode падает уже в архиве.

**Портал приведён в порядок в тот же день (проверено 2026-07-28 глазами):** App ID
`com.fatvpn.fatvpnApp.FatVpnWidget` («FatVPN Widget», explicit) существует, App
Groups включена и привязана к `group.com.fatvpn.fatvpnApp`, профиль `FatVpnWidget
App Store` активен и в его Enabled Capabilities значится App Groups — то есть
entitlement переживёт подпись. Сертификат в команде один (Distribution, создан
API-ключом Codemagic), так что рассинхрона профиля и сертификата быть не может.

**А сборка 143 всё равно упала — на новой проверке:** профиль в портале есть, но в
`~/Library/MobileDevice/Provisioning Profiles` на раннере его не оказалось, при том
что два других профиля там лежали. Фетч подписи Codemagic делает **один раз, до
первого шага скрипта**, по подстроке из `ios_signing.bundle_identifier` — то есть
его результат зависит от того, что было в портале на момент старта сборки, а
профиль виджета создали как раз в те же минуты. Почему до 136-й всё работало без
этого разговора: bundle id было два, и профили на них лежали в портале с 21 июля.

Сборка 145 закрыла вопрос: профиль лежал в портале уже полчаса, а доехали ровно два
(`…​.fatvpnApp` и `…​.PacketTunnel`) — значит его не отдаёт **поиск**, а не портал.
Почему именно — неважно; важно, что искать по bundle id больше не надо.

Шаг `Fetch every App Store profile this team has` забирает **все** активные
`IOS_APP_STORE`-профили команды (`app-store-connect profiles list --save`) в тот же
каталог, откуда читает `use-profiles`. Фильтровать нечего, и четвёртое расширение
когда-нибудь не потребует правок. Важно, что это `profiles list`, а не
`fetch-signing-files`: последняя тянет ещё и сертификаты и без приватного ключа
(он у интеграции) падает с `Cannot save Signing Certificates without certificate
private key` — на этом умерла сборка 144.

Если этот App ID когда-нибудь придётся заводить заново (портал, руками —
capability с конкретной группой через App Store Connect API не выставляется):

1. developer.apple.com → Certificates, Identifiers & Profiles → Identifiers → **+**
   → App IDs → App.
2. Explicit Bundle ID = `com.fatvpn.fatvpnApp.FatVpnWidget`, описание любое.
3. Включить **App Groups** → Configure → выбрать `group.com.fatvpn.fatvpnApp`
   (ту же, что у Runner и PacketTunnel), Save.
4. Там же → Profiles → **+** → App Store → выбрать этот App ID → сертификат
   Distribution → имя вида `FatVpnWidget App Store`. **Не рассчитывать, что
   Codemagic создаст профиль сам**: на этом аккаунте все три профиля сделаны
   руками, а `--create` в `fetch-signing-files` срабатывает, только когда поиск по
   подстроке не вернул вообще ничего. Именно на этом и упала сборка 142.
5. Перезапустить `ios-release`. NE-capability виджету не нужна (см. §1).

Шаг `Verify a profile was fetched for every bundle id` в `codemagic.yaml`
проверяет все три bundle id **до** архива и печатает этот же список действий —
чтобы следующий такой промах стоил секунд, а не полной сборки.

**Обновление таймлайна.** Виджет не опрашивает ничего: `reloadAllTimelines()`
зовут те, кто знает об изменении (приложение и расширение туннеля), а таймлайн
содержит одну запись с `.after(+15 мин)` — только как страховка на случай
потерянного reload. Просить перерисовку раз в минуту нельзя: WidgetKit срежет
бюджет и заморозит виджет на часы. Часы сессии рисует `Text(date, style: .timer)`
— он тикает сам, без перезагрузок.

**iOS 17 `containerBackground`.** Без него виджет рисуется на системном материале
(светло-сером под светлыми обоями) — с нашим белым текстом поверх. Модификатор
`fatVpnWidgetBackground()` включает фон под iOS 17+ и обычный `.background` ниже.

## 5. Диплинки

| Ссылка | Что делает |
|---|---|
| `fatvpn://widget/connect` | приложение подключается к текущему выбору |
| `fatvpn://widget/disconnect` | приложение опускает туннель |
| `fatvpn://widget/toggle` | инвертирует текущее состояние |
| `fatvpn://widget/open` | просто открывает приложение (не действие) |

Кто ими пользуется после появления отдельной кнопки: на Android — только
фолбэк «подключение требует экрана» (`connect`), на iOS ≤ 16 — сама кнопка
(`toggle`). На iOS 17+ действие идёт мимо диплинка, через App Group (§4).

Хост `widget` перехватывается в `AuthController._handleUri` **до** разбора
короткого токена. Это заодно чинило скрытый дефект: раньше любой `fatvpn://`-URI
превращался в «ключ», и `fatvpn://widget/connect` вызвал бы диалог «принять
ключ `connect`?».

Действие паркуется в `AuthController.pendingWidgetAction` и забирается ровно один
раз (`consumeWidgetAction`). Так надо потому, что тап по виджету обычно
**холодно стартует** приложение: ссылка разрешается внутри `AuthController.start()`,
за несколько кадров до появления `HomeScreen`. Подключение к тому же ждёт списка
серверов — `HomeScreen._maybeRunWidgetAction` откладывает действие до конца
`_loadServers`.

Если список **не загрузился** (панель ответила 502, нет сети), тап оплачивает
**одну** повторную загрузку и только потом отбрасывается. Первая версия
отбрасывала сразу, и это поймали на устройстве 2026-07-29: панель отдавала 502,
приложение открывалось с ошибкой, а повторный тап по кнопке виджета не делал
ровным счётом ничего. Ровно один повтор — чтобы лежащий BFF не превращал тап в
цикл запросов.

## 6. Что проверить на устройстве

Ничего из этого не проверено. Порядок — от самого вероятного к падению:

Полный список с критериями провала — `docs/release-test-checklist.md` §2b
(TW1–TW17). Здесь — тот же порядок, коротко.

**Android**
1. Виджет ставится из списка лаунчера; в компактном и широком размере текст не
   обрезан.
2. Подключение из приложения → виджет за секунду показывает «Подключено»,
   локацию и идущие часы.
3. Свайпнуть приложение из недавних (туннель жив) → виджет продолжает показывать
   «Подключено» и правильное время.
4. Тап по кнопке питания при живом туннеле → туннель падает **без открытия
   приложения**, виджет проходит «Отключение…» → «Отключено».
5. Остановить туннель из шторки уведомлений → виджет обновился сам.
6. Force-stop приложения при «Подключено» → следующая перерисовка виджета
   показывает «Отключено» (сверка с живым сервисом), а не вечное «Подключено».
7. Тап по кнопке при отключённом туннеле и выгруженном приложении → «Подключение…»
   → «Подключено», **приложение не открылось**.
8. То же на установке без выбранной страны → подключился лучший узел.
9. Выбрать страну в приложении, выключить, закрыть приложение, тап по кнопке →
   подключилась та же страна.
10. Тап мимо кнопки → открылось приложение, туннель не тронут.
11. Сменить язык в приложении → строки виджета сменились.
12. Выйти из аккаунта → виджет не показывает ни страну, ни часы.

**iOS**
1. Сборка `ios-release` зелёная, включая шаг `Verify App Group entitlement` для
   `FatVpnWidget.appex` (если он красный — не включена capability у App ID).
2. Виджет появляется в галерее, ставится на домашний экран и на экран блокировки.
3. Подключение из приложения → виджет обновился (тут проверяется, что App Group
   реально общий).
4. Убить приложение, дать OS поднять туннель on-demand → виджет показывает
   «Подключено» **без** запуска приложения (проверяет `patchTunnelState` из
   расширения).
5. Выключить VPN в Настройках iOS → виджет показывает «Отключено».
6. Тап **по кнопке** (iOS 17+) → приложение открылось и сразу выполнило
   действие. Это путь App Intent → App Group, диплинк тут ни при чём.
7. Тап **мимо кнопки** → приложение просто открылось, туннель не тронут.
8. На iOS ≤ 16 тап по маленькому виджету → действие выполнено. ⚠️ Здесь
   впервые проверяется, доходит ли `fatvpn://` вообще до Dart на iOS: приложение
   использует `SceneDelegate`, и путь диплинка на iOS никогда не тестировался.
9. Часы на виджете не расходятся с часами на главном экране.

## 7. Известные ограничения

* **iOS ≤ 16: тап по маленькому виджету = переключение.** Интерактивных кнопок
  там нет, `Link` внутри `systemSmall` игнорируется — вся плитка одна кнопка.
  На iOS 17+ и на среднем виджете любой версии разделение полное.
* **iOS: «вкл» и «выкл» всё равно показывают приложение.** Не потому, что оно
  что-то решает, а потому, что поднять и опустить туннель может только оно (§1).
  Приложение выходит на передний план на секунду-две; свернуть себя обратно оно
  не может — iOS такого API не даёт.
* **Android: подключение с виджета стоит фонового движка.** Это полноценный
  Flutter-движок на несколько секунд и уведомление на то же время. Дешевле
  было бы стартовать из конфига на диске — и неправильно (§1).
* **Android: первое в жизни подключение всё-таки откроет приложение** — иначе
  негде показать системный диалог согласия на VPN.
* **`expiresAtMillis` пишется, но нигде не рисуется.** Задел под строку «осталось
  N дней»; сейчас место в раскладке занято таймером сессии.
* На iOS < 14 виджета нет вовсе (WidgetKit появился в iOS 14), приложение
  поддерживает 13.0.
