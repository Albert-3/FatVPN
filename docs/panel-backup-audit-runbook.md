> бэкапа, вскрыть архив, снять версии и ресурсы. **Весь аудит — read-only**:
> ни одной команды, меняющей состояние (никаких `docker compose up/down/restart`,

## 4. Механизм бэкапа — найти и прочитать

Архивы `remnawave_scheduled_YYYYMMDD_HHMMSS.tar.gz` едут в Telegram каждые 6 часов
(увидено 2026-08-06) — ищем, **что** их делает:

```bash
crontab -l
ls -la /etc/cron.d/ /etc/cron.hourly/ /etc/cron.daily/ 2>/dev/null
systemctl list-timers --all
# Скрипт по сигнатурам (sendDocument = отправка в TG; имя файла из архива):
grep -rl --include='*.sh' -e sendDocument -e remnawave_scheduled -e pg_dump /opt /root /usr/local/bin 2>/dev/null
# Готовые инструменты, которые любят ставить:
ls -la /root/remnawave-backup-restore /opt/remnawave-backup-restore 2>/dev/null
# Где лежат сами архивы локально:
find / -name 'remnawave_scheduled_*' -not -path '/proc/*' 2>/dev/null | head
```

Найденный скрипт — **прочитать целиком** (`cat`). Записать: чем сделан (свой скрипт /
distillium / встроенный в панель), расписание, куда шлёт (только Telegram?),
есть ли ретраи, есть ли heartbeat (искать `hc-ping`, `healthchecks` — ожидаем, что нет).

## 5. Вскрыть архив — главный пункт аудита

Три типовых пустышки из §2 плана проверяются здесь.

```bash
BK=$(find / -name 'remnawave_scheduled_*' -not -path '/proc/*' 2>/dev/null | sort | tail -1)
ls -lh "$BK"                # размер: 38.6 МБ при лимите TG 50 МБ — записать точно
tar tzf "$BK"               # СОСТАВ: есть ли .env? docker-compose.yml? дамп БД?
```

Если `.env` в архиве есть — проверить, что в нём **нужные** секреты (v2-панель),
не показывая значений:

```bash
tar xzf "$BK" -O <путь-к-.env-внутри-архива> | grep -o '^[A-Z_0-9]*' | sort
# В списке имён обязаны быть: JWT_AUTH_SECRET, JWT_API_TOKENS_SECRET
```

Если `.env` в архиве **нет** — это находка №1 всего аудита; сверить с живым:

```bash
ls -la <PANEL_DIR>/.env
grep -o '^[A-Z_0-9]*' <PANEL_DIR>/.env | sort    # только имена переменных
```

Формат дампа БД внутри архива (важно для восстановления §2.3): `pg_dump` какого
формата (`-Fc`? plain SQL? `pg_dumpall`?) — видно по расширению/первым байтам и по
скрипту из блока 4.


Записать: Postgres слушает на ____ (если на публичном IP — отдельная находка,
чинится на этапе 3, но знать надо сейчас).

## 8. (Опционально, единственное изменение) Наш SSH-ключ

Чтобы не зависеть от пароля в переписке. Делать только если Роберт не против:

```bash
mkdir -p /root/.ssh && chmod 700 /root/.ssh
echo '<наш публичный ключ>' >> /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
# Проверить с рабочей машины НЕ закрывая текущую сессию: ssh root@95.85.248.65
```

## 9. Забрать копию архива для тестового восстановления (§2.3 плана)

С рабочей машины (архив содержит секреты — хранить как секрет, не в репозитории):

```bash
scp -o PubkeyAuthentication=no root@95.85.248.65:"<путь-к-последнему-архиву>" ./
```

Дальше — §2.3 плана: чистая VM, развернуть, войти в панель, замерить время.
